= Workflow Internals
:navtitle: Workflow internals

This page explains how the workflow engine works inside, for when you need to reason about its behavior.
You don't need it to define or configure workflows.

[[event-routing]]
== Event routing

An event a workflow writes for its own steps reaches only the segment that owns that workflow.
Any other event, including an event published with `publish` / `awaitPublish`, reaches the segments of the workflows that need it:

* the workflows waiting for the event, matched on event name and equality associations, see xref:waiting-for-events.adoc#_filtering_with_associations[Filtering with associations],
* the publisher of a published event, which records its publish step on it,
* for an event a workflow definition starts on, the single workflow the event starts.

A segment hands the event only to those workflows, not to every workflow it owns.
To match waits, each node keeps the open waits of the workflows on the segments it holds.
It loads them from the event store when it claims a segment, from the events tagged `workflowEvent=waitForStep` and `workflowEvent=lifecycle`.
Until a segment has loaded its open waits, or when loading them fails, that segment hands each event to every workflow it owns.

The engine broadcasts an event to every segment, where each segment acts only on the workflows it owns, in these cases:

* The event targets two or more workflows on the segments of one node.
* A workflow definition starts on the event type, and the event starts two or more workflows.
This includes every published event of such a type.
* A segment of the node is still loading its open waits, or failed to load them.
* A segment of the node is still processing the backlog stored before the node started.
* The engine can't read the event values it needs to match the waits or to evaluate a start condition.

An event no segment needs reaches at most one segment, which ignores it.
A segment that receives no events still stores its token, on the processor's claim-extension cycle, once its workflows have no work in progress.
